# Original-installer pilot / Piloto dos instaladores originais

The manual `installer-pilot.yml` workflow runs only on protected main in a disposable
GitHub-hosted Windows VM. It refuses local/self-hosted profiles and existing AIDA installs.
It does not modify the user's installed application, source videos or projects.

The matrix also tests the public 0.8.12 installer from the official site. Its ZIP hash is
3b78ff81ce3b89d46168400b675a5935867703202a193a47be483b8a09cab7eb; the enclosed EXE hash is
e904c7e1c89d6f8094a5f1f6a070fbb8c6882dec46b87a9ca8f22accf59d90e5.

Inputs: original 0.8.14 EXE (SHA-256 088e604644821a1bbfdf6f4e52b76978dcccb58b8774b46f1abb489a3ca40b8e)
retained intact in the private QA draft `qa-reference-0.8.14`; original 0.8.15 EXE
(SHA-256 330f08d0daf617804ea145d0d0594a19d19b16868f6dd6bc54c826d9319585b0)
from verified workflow artifact 14178822854. The temporary draft is not a public software
release and does not relicense the old binary. Only authorized repository writers can read it.

The pilot tests fresh install, original legacy upgrade, exact installed payload hashes,
retired files, parent-exit waiting, reinstall, downgrade refusal, locked-file refusal,
registry/shortcut cleanup and preservation of projects, source videos, preferences, cache,
offline mode and unrecognized user files. It runs the installed frozen CPU self-test before
and after upgrade. It opens a synthetic project fixture carrying the genuine old analysis
reports through the installed EXE's normal startup, captures its own window, checks restored
report bytes and closes gracefully. The fixture container is generated by the current
serializer; it is not claimed to be an old manually saved production project.

Run via Actions -> Isolated original-installer pilot -> Run workflow (main).
Evidence: `original-installer-pilot-evidence`, with `pilot.json`, self-test results,
restored reports and the captured project window. A successful run must report `passed`.
GPU and broader real-video numerical comparisons remain separate validations.

O workflow manual usa VM Windows descartável do GitHub e recusa execução local ou em
runner próprio. Os instaladores originais são conferidos por SHA-256. A referência antiga
fica em rascunho restrito a usuários com acesso de escrita; não é release pública.

O teste cobre instalação, atualização real, hashes, arquivos retirados, espera do processo
pai, reinstalação, bloqueios de downgrade/arquivo em uso, registro/atalhos e preservação
de dados. Executa análise/exportação CPU com os EXEs instalados. Abre uma fixture sintética
com relatórios efetivamente produzidos pela versão antiga, confere os bytes restaurados,
captura a janela do processo de teste e fecha normalmente. O contêiner da fixture é criado
pelo serializador atual; não se declara que foi salvo manualmente na UI antiga.

Executar em Actions, workflow indicado, branch main. Resultado em `pilot.json` deve ser
`passed`. Esta validação não substitui regressão ampla de vídeos reais/GPU.

A matriz testa separadamente upgrades da versão pública 0.8.12 e da referência 0.8.14.
