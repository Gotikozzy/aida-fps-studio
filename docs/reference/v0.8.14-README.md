# AIDA FPS Studio 0.8.14

A abertura mostra o primeiro frame e miniaturas representativas antes de terminar
o índice preciso. É possível explorar a prévia por tempo, trocar de vídeo ou
cancelar a indexação. Marcas, análise e exportação são liberadas com o índice
validado. O preparo do índice continua visível no painel de prévia; reaberturas
aproveitam o índice salvo. Medição e qualidade da exportação permanecem iguais.

Na aba **Início**, use **Nova análise** para abrir uma captura ou **Abrir projeto**
para retomar um `.aida`. A coluna **Tire mais de cada captura** traz exemplos
visuais e dicas de gravação, seleção de trechos e leitura do gráfico.
Os controles principais têm ícone e texto, com orientações nos tooltips em
português e inglês. A análise pode ser consultada e salva no Studio antes de
escolher uma exportação.

Aplicação nativa Windows para analisar FPS e cadência visual de vídeos, organizar
análises e exportar apresentações. Identidade oficial, workspaces de Análise e
Exportação, timeline visual e projetos `.aida`. Interface em português e inglês.

## Instalação

No ZIP com `setup` no nome, extraia o instalador e siga o assistente. O Studio
fica no menu Iniciar, aceita arquivos `.aida` pelo Explorador e pode ser removido
em **Configurações → Aplicativos**. O atalho na área de trabalho é opcional.
O instalador funciona offline e a instalação é feita para a conta atual.

O ZIP portátil de desenvolvimento contém `AIDA-FPS-Studio.exe` e `_internal`,
que precisam ficar juntos. Windows 10/11 x64. O Studio funciona por CPU e a
aceleração NVIDIA pode ser verificada em **Editar → Preferências**.

Para gerar o instalador, execute `build_windows.py` e `package_release.py` antes
de `scripts/build_installer.py`. Passe o caminho do `makensis.exe` do NSIS em
`--compiler`. Use `--qa` para testes internos. A geração pública requer
`--legal-dir` com `Terms.txt`, `LICENSE.txt` e `THIRD_PARTY_NOTICES.md` revisados
para os binários distribuídos. Os ZIPs ficam em `dist/installer/qa` ou
`dist/installer/public` com os respectivos SHA-256.

## Começar uma análise

Na primeira abertura, configure as preferências globais. Na tela inicial, escolha
Nova análise, Abrir análise ou um item recente. Também é possível arrastar um vídeo
ou `.aida` para a janela. As preferências ficam acessíveis pelo menu Editar.
A guia **Início** fica disponível durante o trabalho e mantém o projeto ativo
ao alternar entre as guias. O teste NVIDIA abre uma janela de progresso sobre as
Preferências e mostra o resultado no painel após o término.

Na guia **Análise**, o projeto e os trechos ficam à esquerda, o monitor ao centro
e os resultados/propriedades à direita. Os painéis são redimensionáveis. O painel
Resultados mostra a média medida do trecho, a captura e a referência; os detalhes
ficam em Propriedades. A timeline inferior tem miniaturas, trechos e curva de FPS.

- Clique no vídeo/timeline para navegar; Espaço reproduz e pausa, setas avançam por frame.
- Arraste na faixa Trechos para criar um intervalo. Arraste as alças para ajustar.
- Arraste o corpo de um trecho para movê-lo; o cursor e o monitor acompanham.
  Sobreposições são rejeitadas.
- I marca o início e O encerra e cria o trecho na posição do cursor. O menu da
  timeline oferece os mesmos comandos e permite ajustar o fim da seleção ativa.
- Delete apaga a seleção na timeline/lista. R ativa a ferramenta de seleção e V
  retorna à navegação.
- Ctrl + roda ou o controle Zoom amplia a timeline; a barra inferior permite percorrer.
- Selecione um trecho na lista/timeline; F2 ou duplo clique permite renomear.
- Ctrl+Z/Ctrl+Shift+Z desfaz/refaz seleções. Alterar trechos invalida o resultado
  anterior; mudanças de apresentação não alteram a medição.
- Analisar trechos processa todos os intervalos incluídos na análise.

A janela dedicada de processo mostra a operação, o progresso e o cancelamento.
Ao abrir um vídeo, a janela acompanha a indexação. A timeline fica disponível
quando o índice termina, e as miniaturas da área visível aparecem em segundo plano.
Use **Exibir → Gerar miniaturas novamente** para tentar as que falharam.
Para capturas pesadas, **Exibir → Otimizar prévia** prepara uma região ao redor
do cursor por CPU ou NVIDIA. As marcações usam os timestamps do original.
Em **Arquivo → Cache de índices**, confirme **Reindexar vídeo atual** para refazer
o índice do vídeo aberto ou **Limpar cache de todos os vídeos** para remover os
índices salvos. Na limpeza geral, o projeto aberto continua com seu índice em
memória. Se a reindexação alterar os tempos dos quadros, faça uma nova análise.
O leitor usa quadros-chave para localizar o PTS solicitado. Uma miniatura ilegível
fica marcada na timeline junto das miniaturas disponíveis. Na análise, uma lacuna
separa as sequências comparadas e aparece no relatório LLM com quadros e tempos.
Para uma seleção com quadros ilegíveis, use **Somente relatório LLM** ou ajuste os
trechos para exportar um MP4 com a sequência completa.
O processamento continua fora da interface. A conclusão da entrega depende da
verificação efetiva dos arquivos, preservando o fluxo de gravação seguro existente.

## Projetos .aida

Ctrl+S salva a análise; Ctrl+Shift+S salva como outro arquivo. O `.aida` reúne
manifesto, trechos, configurações e relatórios originais, preservando medições,
PTS, time base, evidências, versões e parâmetros. O vídeo original e os caches
não são embutidos. Ao reabrir, resultados válidos são restaurados sem nova medição.
Se o vídeo foi movido, indique sua localização. Se mudou, os resultados não são
reaproveitados e os trechos precisam ser analisados novamente.

Ao concluir uma nova análise, o Studio oferece salvar o projeto ou atualizar o
arquivo existente. Se a análise começou pela exportação, a entrega segue após a
escolha. Trocar um projeto com mudanças pendentes oferece salvar, descartar ou cancelar.

As metas de apresentação respeitam a taxa nominal da captura. Por exemplo,
29,97 admite 30 FPS, 59,94 admite 60 FPS e 119,88 admite 120 FPS. Metas de um
projeto antigo acima do limite aparecem para revisão antes de exportar.

O salvamento é atômico. As últimas 12 análises abertas/salvas ficam no menu Arquivo
e na tela inicial. Uma recuperação automática de estado é mantida localmente e
pode ser retomada pela tela inicial. Arquivos técnicos completos ficam na área
interna da aplicação e no projeto. Cache é regenerável e não infla o `.aida`.
O formato de projeto é versionado; o código interno continua no pacote `dg_fps`.

## Exportação

Os botões de ação usam ícones vetoriais com dicas ao passar o mouse.
Na guia **Exportação**, escolha nome, pasta e conteúdo e clique no ícone Exportar.
A análise necessária é executada automaticamente e a entrega continua sem outro
comando. Resultados prontos são reaproveitados; cancelar interrompe a sequência.
O comando Analisar continua disponível para conferir resultados antes de exportar.

Use Atualizar prévia para conferir a apresentação real do
quadro atual analisado (ou do primeiro quadro analisado, se o cursor estiver fora).
Escolha nome, pasta, codificação e conteúdo da entrega:

| Opção | Entrega |
|---|---|
| Vídeo e relatório LLM | MP4 H.264 1080p e JSON para LLM |
| Somente vídeo | Apenas MP4 |
| Somente relatório LLM | Apenas JSON; não inicia codificação de vídeo |

A pasta escolhida recebe somente esses arquivos. Mapas de frames, PNGs e demais
JSONs continuam internos. A prévia deve ser atualizada após mudanças de referência,
idioma ou seleção. O relatório LLM contém métricas, cobertura, decisões e orientações
para uma síntese concisa baseada nas medições. Nenhuma LLM é executada pelo aplicativo.
A prévia e os vídeos exportados continuam sem áudio, como nas versões anteriores.

## Evidência espacial e apresentação

O analisador 0.7.0 conserva Optical Flow NVIDIA/Farneback CPU e validação
bidirecional/fotométrica. A ocupação espacial é calculada com toda a máscara de
movimento validado numa grade fixa 8 × 6 antes da amostragem das 32 testemunhas
visuais. Movimento fraco distribuído não é confundido com uma animação local
apenas pela troca de coordenadas das testemunhas. Os limiares são registrados
em `flow_parameters.scope_policy` e a ocupação em `motion_occupancy`.

Durante perda de evidência espacial, o gráfico mantém em pontilhado o último FPS
confiável e aguarda uma janela de recuperação de 1 segundo. A janela de entrada
afetada por avisos pendentes também é pontilhada. Esse desenho não modifica `measured_fps`, os PTS,
os períodos ou os relatórios numéricos. Lacunas de outra natureza continuam com
a projeção entre passado e futuro. Quedas com evidência válida são preservadas.
A política do gráfico é 1.5.0 e consta no relatório para LLM.

O vídeo mantém número por segundo e gráfico por quadro. Captura de 120 Hz pode
conter jogo a 40 FPS, por exemplo. A taxa da captura não é telemetria da engine;
trechos estáticos podem continuar inconclusivos. Dados brutos, decisões heurísticas,
inferências e apresentação continuam separados.

Projetos e relatórios antigos são preservados. Para aplicar o novo analisador a
um vídeo já analisado, execute uma nova análise; exportar um resultado antigo
não reexecuta silenciosamente a medição.

## Preferências e compatibilidade com versões anteriores

A marca pública é AIDA FPS Studio. Dados novos usam a pasta local dessa aplicação.
Preferências anteriores são copiadas quando disponíveis; resultados antigos não
são movidos nem apagados. O menu Arquivo oferece acesso aos resultados anteriores
quando encontrados. O índice temporal existente pode ser reutilizado pelo cache.

## Executar a partir dos fontes

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m dg_fps
```

A pasta é independente do aplicativo principal. Não use o ambiente completo do
DG Graphics Analyzer para empacotar esta distribuição.

## Testar e empacotar

```powershell
.\.venv\Scripts\python.exe -m pytest -q --basetemp=build/test-run
.\.venv\Scripts\python.exe -m ruff check src tests scripts
.\.venv\Scripts\python.exe scripts/build_windows.py
.\.venv\Scripts\python.exe scripts/package_release.py
```

O executável fica em `dist/0.8.1/AIDA-FPS-Studio/`. ZIP Windows e fontes ficam em
`dist/`, com SHA256SUMS.txt. O logo e o ícone oficiais estão incluídos. Para executar
o autoteste do pacote:

```powershell
.\dist\0.8.14\AIDA-FPS-Studio\AIDA-FPS-Studio.exe --self-test C:\pasta-de-teste
```

Use uma pasta vazia. O autoteste verifica CPU, exportação H.264, idiomas, diagnóstico
NVIDIA e a interface nativa. `scripts/validate_studio.py ANALYSIS_JSON` gera provas
visuais da workspace usando medições existentes, sem refazer o detector.
Consulte VALIDATION.md e ARCHITECTURE.md para os detalhes de validação.

A ponte NVIDIA incluída pode ser recompilada com scripts/build_nvidia.py, Visual
Studio C++ Build Tools, CMake e CUDA Toolkit. Esses são requisitos do desenvolvedor,
não do usuário do executável. As dependências estão em requirements-lock.txt.
